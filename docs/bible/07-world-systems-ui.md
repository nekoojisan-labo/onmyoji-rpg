# Bシステム要件定義書（バイブル）: B4 ショップ・経済 / B5 クエスト・進行 / B6 会話・イベント / B7 UI・HUD

舞台＝都「京音都（きょうおとみやこ）」。平安・陰陽師アクションRPG（2.5Dビルボード／アイソメ／Three.js／単機localStorage）。本書は要件・設計レベルで具体化する。実装コードは含まない。

全モジュール共通の最重要原則（デウス・コード踏襲・違反は方針違反とみなす）:
- UIはただ1つの部品 `UIPanel`（固定枠＋ページ送り）で統一する。webスクロールバーは絶対に出さない。溢れた項目は画面下のページ送りで処理する。
- メニューは全画面・固定サイズ・固定作法。アイテム/装備/式神/ステータス/ショップ売買すべて同じ枠・同じ操作で描く。個別描画しない。
- フィールドはマップを広げ、メッセージboxは会話がある時だけ出す。普段は余白。
- イベント・会話の一度きり制御（`oneTime`）を最初から設計に入れる。

# B4. ショップ・経済

## 目的・スコープ
京音都のハブ町・霞ヶ辻（Z01）に置く商店群（武器屋／防具屋／道具屋／宿屋）の仕様、宿屋回復料金・セーブ拠点運用を確定する。**品揃え・価格・売買レート・通貨は 00b-data-master.md（§1/§6）が正**で本書は参照に留める。売買UIは B7 の `UIPanel` 全画面枠を流用し、ショップ独自UIは作らない。

スコープ内: 4店種の機能仕様、宿屋回復料・セーブ拠点運用、購入制限、ショップUI作法。**品揃え・価格・売却レート・通貨は自前で持たず 00b-data-master.md（§1 通貨／§6 アイテムマスター）を正として参照する。**
スコープ外: 装備の能力値計算式（B3）、アイテム効果の戦闘適用（B1）、合成・強化・行商人ランダム在庫（v2送り）、価格・売却レートの数値定義（00b §1/§6 が正）。

## 通貨設計
- 通貨・価格・売却レートの正典値は **00b-data-master.md §1（通貨）** を参照（本書では再掲しない）。
- 確定事項の要点のみ: 通貨単位＝「文（もん）」一本化（旧「銭」廃止）、所持上限 `999,999文`、超過分は切り捨て＋HUDに「これ以上は持てぬ」、売却レート `SELL_RATE=0.5`（売値=floor(買値×0.5)）、セーブ格納は単一整数 `save.gold`。
- 入手源: 妖魔ドロップ（B1）、宝箱（B3/B5）、クエスト報酬（B5）、アイテム売却（B4）。
- 第1章の想定資金カーブ（仮・バランス基準）:

| 進行点 | 累計入手目安(文) | 想定残高(文) | 設計意図 |
|---|---|---|---|
| 霞ヶ辻到着直後 | 0 | 150（初期所持） | 道具屋で消耗品1〜2個が買える |
| フィールド1踏破 | +400 | 〜450 | 武器か防具のどちらか片方を更新可 |
| ダンジョン中盤 | +600 | 〜700 | 両方更新 or 守り札を備蓄 |
| ボス撃破後 | +800 | 〜1,000 | 第2章への持ち越し（強い装備に1段手が届かない＝引き）|

設計原則: 第1章クリアまでに「武器1段＋防具1段」は買えるが「全部入り」はできない。選択を強いる。

## 店舗共通仕様
- 入店トリガー: 店NPCに話しかける（B6会話）→「何用じゃ」→ `[買う / 売る / やめる]` の3択。選ぶと B7 の全画面 `UIPanel`（ショップモード）へ遷移。
- パネル左＝品目リスト（ページ送り）、右＝選択中アイテムの説明＋価格＋所持金。個数表示（「Xコ／なし」）は出さない（デウス方針）。
- 購入: 所持金が足りれば即購入、足りなければ「文が足りぬ」。購入後は所持金即時更新＋localStorage保存。
- 売却: 所持アイテムを並べ、売却額（買値×レート）を表示。装備中アイテムは売却不可（リストにグレー表示・選択不可）。
- 重要アイテム（クエストキー等）は売買リストに出さない（`sellable:false`）。
- 操作: 上下＝項目選択、決定＝確定、戻る＝1階層戻る、ページ送り＝下端到達で次ページ。マウス/タップでも同操作。

## B4-1 道具屋（消耗品）
- 品揃え・効果・価格の正典は **00b §6.1 消費アイテム** を参照（傷薬／上傷薬／気付け丸／浄め札／解呪札／守り札／戻り札）。本書では再掲しない。
- 旧「霊鈴（MP+40）」は 00b で **気付け丸（気+40）** に統合済（MP表記廃止＝気へ一本化）。旧「浄め札＝状態1種解除のみ」は 00b で **状態1種解除＋穢−5** に拡張、別途 **解呪札（呪詛/封解除＋呪抵抗一時+20）** が分離。
- 設計注記（モジュール固有）: 購入上限は1品目あたり同時所持 `99個`（00b maxStack準拠）。第1章は在庫無限（売り切れなし）。

## B4-2 武器屋（主人公の呪具）
主人公は式神オンリーで直接近接で殴らないが、符・呪の威力に効く「呪具（じゅぐ）」を1つ装備する（B3）。
- 品揃え・補正・付帯・価格の正典は **00b §6.2 武具マスター（呪具）** を参照（笏／桃の木剣／霊符の杖／黒鉄の槌）。本書では再掲しない。
- 補正は 00b では「体」「術力」に分離（旧「攻撃補正+N」は呪具種により体or術力へ振り分け。例: 霊符の杖＝術力+6・最大気+10）。
- 設計注記: 第1章はこの4種のみ販売。上位（妖刀系）は第2章解禁。

## B4-3 防具屋（装束・装飾）
装備枠は B3 準拠（装束1／装飾1）。
- 品揃え・補正・付帯・価格の正典は **00b §6.2 武具マスター（装束・装飾）** を参照（白の狩衣／蒼の狩衣／紅の袍／五行の守り／白虎の守り 等）。本書では再掲しない。
- 名称統一（00b基準）: 旧「五行護符」→ **五行の守り**、旧「白虎の護符」→ **白虎の守り**（区分=装飾）。防御補正は「護+N」、被会心率補正は 00b では「被会心率−15%」表記。

## B4-4 宿屋（休息・回復・オートセーブ拠点）
- 機能: 一泊で主人公HP/気 全回復＋使役中・控えの全式神HP回復（式神の気は主人公の気プール共有＝00b §4）＋軽度状態異常を解除＋休息による穢の軽減（−／00b §2.3 減少源）。
- 配置: 宿屋は **霞ヶ辻（Z01）に配置**（裁定）。第1章のセーブ拠点はここ。
- 料金（仮・進行で段階化）:

| 宿 | 場所 | 料金(文) | 効果 |
|---|---|---|---|
| 霞ヶ辻の旅籠 | Z01 霞ヶ辻 | 30 | 全快（HP/気/状態異常）＋休息で穢軽減 |
| （第2章以降の宿） | 各章ハブ | 章ごとに+20 | 同上 |

- セーブ連動: 宿泊確定時に**オートセーブ**（B5/A3のセーブ呼び出し）。井戸での手動セーブと併せ、セーブ手段は「宿屋オートセーブ＋井戸手動」の2系統（裁定。ゾーン遷移クイックセーブはv2）。
- 演出: 宿泊選択→暗転→「ぐっすりと眠った……」→全快SE→明転。会話UI（B6）の1カットイベントとして実装。

## 価格バランスの考え方（指針）
- 売却レート一律 = 買値 × 0.5（端数切り捨て）。`SELL_RATE = 0.5` 定数で管理（ハードコード散在禁止）。数値定義は 00b §1。
- 妖魔1体の文ドロップは「傷薬1個（30文）前後／中型は上傷薬1個（90文）前後」を基準にチューニング（具体ドロップ・文量は 00b §5 敵ステ表が正）。
- 装備の買値は「その地点で平均10〜15分プレイすれば1つ買える」を目安に置く（具体価格は 00b §6.2）。

## データ構造
ショップ定義（例・概念）:
```
ShopDef {
  id: "shop_dougu_kadomachi"
  type: "tool" | "weapon" | "armor" | "inn"
  npcId: "npc_dougu_aruji"
  stock: [ { itemId, restock: "infinite", chapterUnlock: 1 } ]   // inn は inn パラメータ
  inn: { healCost: 30, fullHeal: true, autosave: true }          // type==="inn" のみ
}
ItemDef（B3共有）に price{buy, sell}, sellable, chapterUnlock を持つ
```
- 所持金は単一の整数 `save.gold`（00b §1）。全取引は immutable に新残高を算出してから保存（コーディング規約: ミューテーション禁止）。
- ItemDef の price{buy, sell}・sellable・chapterUnlock の値は 00b §6 を正とし、B3/本書では再定義しない。

## 受け入れ基準
- 4店種すべてが同一 `UIPanel` 全画面枠で開く（独自レイアウト・スクロールバーが出たら不合格）。
- 所持金が足りない購入は拒否され、残高が変化しない。
- 装備中・`sellable:false` のアイテムは売却リストで選択不可（00b で取引不可指定の笏/白の狩衣/喰い鬼ドロップ等を含む）。
- 売値が常に `floor(買値×0.5)` と一致する（00b §1 SELL_RATE）。
- 宿泊で全快し、オートセーブが走り、リロード後も残高・回復状態が保持される。
- 所持金上限 999,999文 を超えない（切り捨て＋警告表示）。
- 第1章クリア時点の標準プレイで「武器1段＋防具1段」が買え、「全種制覇」は不可能。
- 全品揃え・価格が 00b §6 と一致する（本書に独自の数値テーブルを持たない）。

# B5. クエスト・進行

## 目的・スコープ
メインシナリオの進行フラグ設計、サブクエスト構造、MMO風クエストログ／トラッカー（常時表示の現在目標バナー＋全画面ログ）、報酬を確定する。デウス・コードの `quest-system.js`（QUEST_STEPS＝背骨、storyFlagsから現在目標を導出）を正統踏襲する。

スコープ内: フラグ契約、クエストデータ構造、現在目標の導出ロジック、報酬付与のデータ供給。クエスト一覧の**内容正典は 00b §7（C4の5本）**、本書はそのフラグ/構造を供給する（役割分離）。
スコープ外: クエスト報酬アイテムの効果（B1/B3）、会話分岐の文面（C4/B6）、マップ配置（C5）、クエスト一覧の**内容定義**（00b §7 が正）。
- **役割分離（裁定）**: クエストログUIの**描画担当は B7**（`UIPanel`）。**B5 はデータ供給**（フラグ・構造・現在目標の導出）に専念し、UIを直接描かない。トラッカー/ログの見た目仕様は B7 を正とする。

## 進行アーキテクチャ（背骨＝QUEST_STEPS）
- メイン進行は順序付きの `QUEST_STEPS` 配列で定義する。各ステップは `done(storyFlags)` 関数を持ち、storyFlags から「達成済みか」を導出する（達成状態を二重に持たない＝単一の真実源は storyFlags）。
- 「現在の目標」= QUEST_STEPS を先頭から走査し、最初に `done()===false` になったステップ。これを `refreshObjective()` が算出し、バナーに反映。
- `refreshObjective()` の呼び出し点（デウス教訓そのまま）: ゲーム開始 / ロード / マップ遷移時(onEnterMap) / NPC相互作用後(checkInteractions) / 戦闘UI復帰時 / イベント終了時(endEvent)。呼び忘れると目標が更新されないため、この6点を必須とする。

## 第1章 メインクエスト ステップ表（背骨）
> 背骨・フラグ・目標文の正典は **00b §7.2 メイン進行 背骨（QUEST_STEPS）**。以下はその供給用の写し（差異が出たら 00b を正とする）。クエストの内容（giver/報酬/セリフ連動）は 00b §7.1。

| 順 | stepId | 目標文（バナー表示） | 達成条件 done() | 成立フラグ |
|---|---|---|---|---|
| 1 | ch1_arrival | 陰陽寺の師に会う | metMaster | metMaster |
| 2 | ch1_townTask | 霞ヶ辻の異変を聞き込む（3人） | townHeard>=3 | townHeard(int) |
| 3 | ch1_toField | 西院の枯野へ向かう | enteredField1 | enteredField1 |
| 4 | ch1_fieldClear | 枯野の妖気の源（泥眼の女）を断つ | fieldSourceCleared | fieldSourceCleared |
| 5 | ch1_dungeon | 羅城門・地下に入る | enteredDungeon1 | enteredDungeon1 |
| 6 | ch1_shikigamiGet | 封ぜられし力を解く（演出/玄の再確認） | shikiUnsealed | shikiUnsealed |
| 7 | ch1_boss | 羅城門の喰い鬼を祓う | bossDefeated | bossDefeated |
| 8 | ch1_complete | 寺へ帰還し師に報告 | chapter1_complete | chapter1_complete |

フラグ契約（最低限・命名固定）:
`metMaster / townHeard(int) / enteredField1 / fieldSourceCleared / enteredDungeon1 / shikiUnsealed / bossDefeated / chapter1_complete`。
- ch1_shikigamiGet は 00b 裁定で**演出/玄の再確認**に再定義（玄の契約はプロローグ既済・v1使役式神=玄のみ）。フラグ↔ゾーンID(C5)↔STEP の対応は 00b §7.3 を正とする。

進行フラグの配線方針（デウス踏襲）:
- NPC名（npcId）ベースで `checkInteractions` に配線（師＝metMaster、ボスシンボル＝撃破CBで bossDefeated）。
- 場所フラグは `onEnterMap` で立てる（enteredField1 / enteredDungeon1）。
- ボス撃破CBの未配線は最大の事故ポイント（デウスで boss_defeat が一度も発火しなかった実例あり）。startBattle の `onBossDefeat` コールバックを必ず使い、撃破時に `bossDefeated=true` → `refreshObjective()` を呼ぶ。

## サブクエスト構造
- 受注: サブクエストNPCに話しかけ、依頼を受けると `quest.state = "active"`、ログに追加、トラッカーに（メインの下に）副目標として表示。
- 状態機械: `inactive → active → (条件達成) readyToReport → complete`。報告NPCで `complete`、報酬付与。
- 一度きり制御: クエスト完了は `oneTime`（save.questFlags に記録）。完了済みクエストは再受注不可、報告NPCのセリフが「礼を言うぞ」固定に切替。

第1章サブクエスト:
> 旧B5の3本（sq_lost_charm/sq_kitsune_hunt/sq_lantern）は**廃止**。第1章クエストは **00b §7.1（C4の5本）が内容正典**＝メイン `mq_ch1_kamikakushi`＋サブ4本（sq_maigo_kanzashi／sq_shimetta_ayakashi／sq_doki_tanomi／sq_kataribe_uta）。B5 は各クエストのフラグ/状態機械/受注前提を供給する（giver・条件・報酬・セリフは 00b §7.1 を正とする）。
- フラグ完了名と立つ契機（sq_kanzashi_done 等）は 00b §7.3 対応表を参照。全クエスト `oneTime:true`（`save.questFlags` 記録・二重報酬不可）。

## クエストログ／トラッカーUI（MMO風）
> **役割分離（裁定）**: 以下は表示の**要件仕様**であり、実際の**描画は B7 の `UIPanel` が担当**する。B5 は表示すべきデータ（現在目標・サブ目標・状態・報酬）を供給するのみ。

常時表示バナー（トラッカー）:
- 画面の固定位置（B7規定の右上・アイソメ視界を遮らない位置）に「現在目標」を1行常時表示。例: 「▸ 西院の枯野へ向かう」。
- メイン目標を最上段、アクティブなサブ目標を最大2件まで下に。3件超は「ほか N件」で省略（ここでもスクロールバーは出さない）。
- 目標更新時に短くハイライト（フェード）。完了時に取り消し線→消える。

全画面クエストログ（メニューから／`UIPanel`）:
- メニューの「巻物（クエスト）」から全画面 `UIPanel` で開く。
- 左＝クエスト一覧（タブ: メイン／依頼）、右＝選択クエストの説明・現在状況・報酬。
- 一覧は固定枠＋ページ送り（スクロールバー厳禁）。完了済みは末尾にグレーで。
- 状態表記: 進行中＝「進行中」、報告待ち＝「達成（報告へ）」、完了＝「完了」。

## 報酬
- 報酬は `reward { gold, items[], shiki?:string, exp? }`。クエスト完了時に一括付与し、付与内容を会話UIに列挙（「○○を手に入れた」）。報酬の具体値は 00b §7.1 を正とする（gold は文・00b §1）。
- メインステップ ch1_shikigamiGet は 00b 裁定で**演出/玄の再確認**（玄の契約はプロローグ既済・v1使役式神=玄のみ）。`save.shiki` への新規追加ではなく封印解除演出として実装。燼は第2章契約。
- 報酬付与も immutable（新stateを作って保存）。

## データ構造
```
QuestDef {
  id, type: "main" | "side",
  title,
  objectiveText,              // バナー/ログ表示文
  steps?: [ { id, text, done(flags) } ],   // main は QUEST_STEPS と連動
  giverNpc, reportNpc,
  prereq: [questId|flag],     // 受注前提
  reward: { gold, items:[{itemId,qty}], shiki?, exp? },
  oneTime: true
}
save.storyFlags: { ...bool/int }      // 単一の真実源
save.questFlags: { [questId]: "inactive|active|readyToReport|complete" }
```

## 受け入れ基準
- 現在目標は storyFlags のみから導出され、フラグ達成→次目標へ自動で進む（達成状態の二重管理が無い）。
- `refreshObjective()` が規定6点すべてで呼ばれ、目標表示の遅延・取りこぼしが無い。

# B6. 会話・イベント

## 目的・スコープ
NPC会話／キャラ同士の会話／カットシーンの会話システム、イベント発火と一度きり制御（`oneTime`）、会話UIの作法を確定する。デウスの `story-events` / oneTime 教訓を踏襲。

スコープ内: 会話データ構造、分岐・選択肢、話者表示、イベントトリガーと一度きり制御、駆け寄り会話、カットシーン進行、会話UI作法。
スコープ外: 文面そのもの（C4）、ボイス（v1は無し）、戦闘演出（B1）。

## 会話の種類
1. NPC会話: マップNPCに話しかけて発火。状態（storyFlags）で分岐する。
2. キャラ同士の会話: 主人公↔NPC／式神↔主人公の掛け合い。話者を切り替えて立ち絵＋名前を出す。
3. カットシーン: 操作不能の演出シーケンス（暗転・立ち絵入退場・テキスト・SE・カメラ寄り）。章の節目・ボス前後に挿入。
4. 駆け寄り会話（デウス踏襲）: 特定NPCが主人公へ接近し、到達距離（仮 40px）で自動発火（仲間NPC合流・師の呼び止め等）。`updateApproachNPCs()` 相当をプレイヤー更新後に毎フレーム呼ぶ。

## 会話UI作法（共通）
- フィールドのメッセージboxは会話がある時だけ表示（普段は出さず余白）。デウス方針の厳守。
- 1メッセージ＝1ページ。長文は自動でページ分割（固定枠に収め、スクロールバーは出さない）。決定で次ページ。
- 話者名は枠左上に表示。立ち絵（ビルボード/2D portrait）は枠の左 or 右に1人ずつ。同時表示は最大2名（左右）。
- 文字送り: 1文字ずつ表示（仮 30ms/字）、決定キーで全文即時表示→もう一度で次へ。
- 選択肢は同じ `UIPanel` の固定枠内に縦並び（最大4択）。上下選択＋決定。
- 会話中はプレイヤー操作・敵AIを停止（カットシーンは特に厳格に入力ロック）。

## イベント発火と一度きり制御（oneTime）
発火トリガー種別:
- `onTalk`: NPC会話起点（npcId＋storyFlags条件）。
- `onEnterMap`: マップ遷移時（場所到達イベント・初回ナレーション）。
- `onZone`: マップ内の見えないトリガーゾーンに侵入（イベント床）。
- `onFlag`: 特定フラグが立った瞬間（連鎖イベント）。
- `onBossDefeat`: ボス撃破コールバック（B1連動）。

一度きり制御（デウスの最重要教訓）:
- 各イベントは `oneTime:true|false`。`oneTime` なイベントは発火時に `save.eventFlags[eventId]=true` を立て、以後スキップ。
- 「一度きりのはずが毎回出る／場所イベントが再入で再発火」はデウスでの典型バグ。発火判定は必ず `eventFlags` を先に確認してから実行する設計を契約とする。
- カットシーン終了（endEvent）で `eventFlags` 記録＋`refreshObjective()`（B5）＋必要なら storyFlags 更新を必ず行う。
- 駆け寄り会話・合流イベントも oneTime（合流後はNPCを `isNPCHidden` で描画/衝突/会話から除外＝デウス踏襲。再戦闘・うろつき残りを防ぐ）。

# B7. UI・HUD

## 目的・スコープ
MMO風HUD（HP/気バー・ホットバー・ミニマップ・クエストトラッカー・穢ゲージ）と全画面メニューを確定する。デウスのUI統一思想を厳守: ただ1部品 `UIPanel`（固定枠＋ページ送り）、webスクロールバー厳禁、メニューは全画面固定作法（アイテム/装備/式神/ステータス/ショップ売買すべて同枠）。アイソメ画面上のHUD配置を規定する。

スコープ内: 画面レイアウト、固定枠サイズ、HUD各要素、ホットバー、ミニマップ、全画面メニューの構成と操作、`UIPanel` の責務。
スコープ外: 各データの中身（B1〜B6が供給）、アセット画像（C6）。

## 画面レイアウト（固定枠・デウス踏襲）
- ゲーム描画領域は固定サイズ枠（仮 960×640、16:10。アイソメの視界が成立する比率）。viewport（フィールド描画）＋下部UI帯を固定で積む。webのスクロールバーは一切出さない（`overflow:hidden`）。
- アイソメ視界を遮らないよう、HUDは画面四隅・下帯に寄せ、中央は空ける。
- レスポンシブはコンテナごと等比スケール（CSS transform scale）。内部の論理座標は固定（デウスの固定px方式）。タッチ操作は仮想パッド＋ホットバータップ。

## HUD要素（常時表示・フィールド/戦闘）
配置（アイソメ画面上）:
- 左上: 主人公ステータス。HPバー（赤）／気バー（青・旧MP表記廃止＝00b §2）／Lv・名前。バーは数値併記（120/180）。
- 左上・下段: 使役中の式神アイコン＋式神HPバー（1体ぶん。控えはメニューで。式神の気は主人公の気プール共有＝00b §4のため式神個別の気バーは出さない）。
- 右上: クエストトラッカー（B5供給・現在目標1行＋サブ最大2件。描画はB7）。
- 右下: ミニマップ。
- 下中央: ホットバー（式神召喚・切替／呪術／符／鎮魂／道具のスロット）。
- 上中央（一時表示）: 状態異常アイコン・バフ残時間・**穢ゲージ**（00b §2.3・段階で色変化）・「文が足りぬ」等のトースト。

### HP/気バー
- 主人公HP/気、式神HPを表示。減少時に短いダメージ演出（バーが追従して減る）。瀕死（HP25%以下）で点滅。
- 穢ゲージは段階表示（平常/軽い穢40+/重い穢70+/暴走100）。重以上はデバフ中アイコンを併記（00b §2.3）。

### ホットバー（式神/呪術/符/鎮魂/道具・8スロット）
- スロット数: **8**（1〜8キー／タップ）。割当はメニューの「式神（編成・ホットバー割当）」画面から行う。
- **B1入力との対応は 00b §7.4 ホットバー⇄B1入力対応表を正とする**。要約: 1=式神召喚/帰還（玄）・2=式神予約（燼）・3=式神切替(E)・4/5=呪術(K/L)・6=符投げ(J・気消費なし)・7=鎮魂チャネル（鎮魂窓中の専用入力・00b §2.4）・8=道具(Q・クイック札)。
- 種別タグで色分け（00b §7.4 識別色）: 呪術=青／符・道具=緑／式神=単色紫（紫グラデは禁止だが識別色としての単色紫は可）／**鎮魂=金**。クールダウンは円形クールダウン表示（残時間オーバーレイ）。
- 気不足・CD中・所持0は暗転＋使用不可＋残時間表示。鎮魂スロットは鎮魂窓（敵HP30%以下）が開いた時のみ点灯（00b §2.4）。

### ミニマップ
- 右下固定。現在マップの簡易俯瞰（歩行可エリア・出口・主要NPC・クエスト目標マーカー）。
- 北固定（回転なし）。主人公＝中央の自機マーカー。クエスト目標は B5 の現在ステップから黄マーカー。
- 全体マップ（章マップ）はメニューから全画面 `UIPanel` で別途確認。

## 全画面メニュー（`UIPanel` 統一・FF風固定作法）
- 開閉: メニューキー（Esc/M／メニューボタン）。開くと半透明オーバーレイ＋全画面 `UIPanel`（`.menu-overlay.active .ui-panel--frame` 全画面化）。フィールド/戦闘は背後で停止。
- トップメニュー項目（縦1列・デウスのL/R衝突回避踏襲で縦並び固定）:
  `道具 / 装備 / 式神 / 巻物（クエスト）/ 全体図（マップ）/ ステータス / 設定 / セーブ / ロード / 戻る`
- セーブ/ロード導線（裁定整合）: メニューの「セーブ」は**井戸での手動セーブ**に対応（拠点外でも井戸シンボルで起動。宿屋泊は自動でオートセーブ＝B4）。「ロード」は保存済みスロットの読み込み。ゾーン遷移クイックセーブはv2のため本メニューには出さない。
- 全サブ画面が同一 `UIPanel`（左＝リスト＋ページ送り、右＝詳細）で描かれる。個別レイアウト禁止。

各サブ画面:
| 画面 | 左ペイン（リスト・ページ送り） | 右ペイン（詳細） | 主な操作 |
|---|---|---|---|
| 道具 | 所持消耗品 | 効果説明・使う/捨てる | 使用→対象選択 |
| 装備 | 装備枠（呪具/装束/装飾） | 候補一覧＋増減差分 | 付替え |
| 式神 | 所持式神（v1は玄のみ） | 能力・スキル・召喚/控え設定 | 編成・ホットバー割当 |
| 巻物 | クエスト（メイン/依頼タブ） | 説明・状況・報酬 | タブ切替 |
| 全体図 | 章マップ | 現在地・目標 | — |
| ステータス | 主人公/各式神 | 詳細パラメータ（00b §2 の8項目: HP/気/体/護/術力/速/CRT率/critMul） | 切替 |
| 設定 | 項目（音量等） | 値 | 増減 |

- 装備枠は呪具1／装束1／装飾1の3系統（00b §6.2・旧「護符」は装飾に統一）。
- 個数表示（「Xコ／なし」）は出さない（デウス方針）。
- ショップの購入/売却も同じ `UIPanel` 枠（B4）。メニューとショップで作法が一致する。

### ゲームオーバー画面とメニュー導線（裁定整合）
- 主人公HPが0になると専用のゲームオーバー画面（全画面 `UIPanel`）へ遷移する。フィールド/戦闘は停止。
- 選択肢（縦1列）: `直前のセーブから再開（ロード）／タイトルへ戻る`。
- 「直前のセーブから再開」は**宿屋オートセーブまたは井戸手動セーブ**の最新スロットを読み込む（メニューの「ロード」と同一経路を再利用）。セーブ拠点（宿屋＝霞ヶ辻Z01／井戸）以降の進行は巻き戻る。
- ゲームオーバーからの新規セーブは行わない（ロード/タイトルのみ）。通常のセーブ/ロードはメニュー（上記）とB4宿屋から行う。

## `UIPanel` 部品の責務（中核契約）
- frame（固定枠）＋ `paintList`（ページ送り描画）＋詳細ペイン描画を提供する単一部品。
- 入力: 上下＝項目移動、左右＝タブ/キャラ切替（縦リスト時は無効）、決定、戻る、ページ送り（下端で次ページ・上端で前ページ）。
- 溢れ処理は必ずページ送り。webスクロールバーを出した時点で仕様違反（自動テストで `scrollHeight>clientHeight` を検出したら失敗扱い）。
- メニュー／ショップ／クエストログ／会話選択肢／全体図の全てがこの部品を再利用する。

## アイソメ画面上のHUD配置・受け入れ基準
- HUDは四隅＋下帯のみ。アイソメ中央視界に被らない（プレイ中、足元・前方の妖魔がHUDで隠れない）。
- 全メニュー・ショップ・クエストログ・会話選択肢が同一 `UIPanel` で開き、作法（操作キー・枠・ページ送り）が一致する。
- どの画面でも webスクロールバーが出ない（出たら不合格）。
- ホットバー8スロットが 00b §7.4 の対応表（式神/呪術/符/鎮魂/道具）とB1入力で一致する。CD・気不足・所持0が視覚的に明確（暗転・残時間表示）。鎮魂スロットは鎮魂窓のみ点灯。
- ミニマップに現在地・出口・クエスト目標が表示され、北固定で回転しない。
- 等比スケールで縮小しても内部レイアウトが破綻しない（論理座標固定）。
- メニュー項目は縦1列で、L/R＝キャラ切替とUp/Down＝項目選択が衝突しない（デウスの実バグ回避）。
- ゲームオーバー画面からロード/タイトルへ遷移でき、メニューのセーブ/ロード（井戸手動）とB4宿屋オートセーブの導線が破綻しない。
